# CLAUDE.md

Orientation for working in this repo. See `README.md` for setup/run steps and
`assets/images/SOURCES.md` for image licensing status — this file covers
architecture and conventions instead of repeating them.

## What this is

EcoSync-CropGuard: an offline-first crop disease reference/diagnostic app for
Zimbabwean smallholder farmers, covering 5 crops (maize, tobacco, groundnuts,
sorghum, sweet potatoes), Android only (Flutter/Dart, `minSdk` 21). Diagnosis
is a symptom/photo lookup tool, not a trained image classifier — there's no
ML model and no training pipeline. The one exception is `PhotoMatchService`'s
beta "Photo Lookup" feature, which ranks a captured/picked photo against the
reference image set using perceptual-hash (aHash) visual similarity, entirely
on-device and with no learned model — see `lib/utils/phash.dart`. See
`kDisclaimer` and `kPhotoLookupDisclaimer` in `lib/utils/constants.dart` for
the decision-support framing shown in-app.

## Architecture

- **State management**: a single `Provider`/`ChangeNotifier`
  (`lib/providers/app_state_provider.dart`), created once in
  `lib/app.dart` (`EcoSyncApp`) and read via `context.watch`/`Consumer`.
  There's no second provider and no Bloc/Riverpod/GetX — don't introduce one
  for a single new screen; extend `AppStateProvider` or add a service instead.
- **Navigation**: plain imperative `Navigator.push(MaterialPageRoute(...))`
  from screen to screen. No named routes, no router package (go_router etc.).
- **Data layer — the one thing most likely to surprise a newcomer**:
  `assets/db/cropguard.db` is a **pre-built, read-only SQLite file**, not
  something the app builds at runtime. It's generated by
  `scripts/populate_db.py` (a standalone, stdlib-only Python script — not a
  Flutter dependency) and bundled as a Flutter asset. `DatabaseHelper`
  (`lib/services/database_helper.dart`) copies it into the app's documents
  directory on first launch and opens it read/write from there via `sqflite`.
  To change disease/crop/treatment content: edit `scripts/populate_db.py`,
  re-run it, then `flutter run` — don't hand-edit the `.db` file or add
  runtime migration logic for content changes.
- **Layers**: `models/` (plain data classes with `fromMap`/`toMap`, one per
  DB table) → `services/` (query logic, one per feature area — bookmarks,
  diagnosis, treatments) → `providers/` (app-wide reactive state) →
  `screens/` + `widgets/` (UI). Screens talk to services directly for
  one-off queries (e.g. `DiagnosticService().getDiseases(...)` in a
  `FutureBuilder`); only cross-screen shared state (crops, bookmarks, theme)
  goes through `AppStateProvider`.

## Directory map

```
lib/
  main.dart          Bootstrap: locks portrait orientation, runApp(EcoSyncApp())
  app.dart           EcoSyncApp (Provider setup) + MaterialApp/theme
  models/            Crop, Disease, Symptom, Treatment, Bookmark — one per DB table
  services/          DatabaseHelper (DB lifecycle + generic query/insert/delete),
                      BookmarkService, DiagnosticService, TreatmentService,
                      PhotoMatchService (perceptual-hash photo similarity)
  providers/         AppStateProvider — crops, bookmarks, loading, theme seed
  screens/           One file per screen; see class-level doc comment on each
                      for what it does and how it's reached
  widgets/           Reusable cards/tiles shared across screens
  utils/constants.dart   Colours, plant-part list/order, theme options, disclaimer text
scripts/
  populate_db.py         Generates assets/db/cropguard.db (schema + seed data)
  generate_phashes.py    Precomputes perceptual hashes for reference photos into
                          scripts/phash_cache.json (needs Pillow — run before
                          populate_db.py, which reads the cache but stays stdlib-only)
  prepare_images.py      Downloads/crops open dataset photos into assets/images/
  compress_image.py      One-off resize/compress helper (ImageMagick substitute)
  generate_icons_test.dart  Rasterizes SVG brand marks to PNG launcher/splash icons
                            (run via `flutter test`, not part of the real test suite)
assets/
  db/cropguard.db        Pre-populated DB asset (see Data layer above)
  images/<crop>/         Reference disease photos, see SOURCES.md for licensing
```

## Conventions

- Dartdoc style: terse, rationale-focused `///` comments above classes (and
  non-obvious methods) — explain *why* something is shaped the way it is,
  not what the code already makes obvious. Skip comments on trivial getters
  and simple presentational widgets. Follow the existing comments in
  `lib/services/database_helper.dart` and `lib/screens/crop_gallery_screen.dart`
  as the reference style.
- Treatment/disease records always carry a `source` field for traceability —
  don't add content to `populate_db.py` without a bibliographic reference.
